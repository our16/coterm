我觉得 **CoTerm** 最有价值的地方，不是再做一个终端，而是重新定义 **AI 与 Terminal 的关系**。

一句话定位：

> **CoTerm = AI Native Terminal Workspace**
>
> **让 Human、AI、Remote、Local 在同一个 Terminal Session 中协同工作。**

---

# 一、项目定位（Positioning）

## Mission

让 AI 真正成为 Terminal 的协作者，而不是终端的"外挂"。

今天所有 AI Coding 工具基本都是：

```text
AI
 │
创建自己的 Terminal

执行命令
```

CoTerm 改变为：

```text

              │
              │
        ┌─────▼──────┐
        │  CoTerm     │
        │ Shared PTY  │
        └─────▲──────┘
              │
              │
             AI
```

AI 不拥有 Terminal。

Human 才是 Owner。

AI 是 Collaborator。

# 十四、技术栈建议

如果目标是做一个长期维护的开源项目，我建议采用分层架构，而不是把所有能力耦合在一起。

```text
CoTerm/
├── coterm-core          # Session、PTY、事件总线（Rust）
├── coterm-server        # 本地服务（Rust）
├── coterm-protocol      # Session API / MCP 定义
├── coterm-desktop       # 桌面 UI（Tauri + React）
├── coterm-agent-sdk     # Python / TypeScript SDK
├── coterm-connectors
│   ├── ssh
│   ├── powershell
│   ├── wsl
│   ├── docker
│   ├── kubernetes
│   └── serial
├── coterm-mcp
└── plugins
```

* **核心（Rust）**：负责 PTY、Session 生命周期、屏幕缓冲、输入仲裁和性能。
* **桌面端（Tauri + React）**：现代 UI、跨平台、资源占用低。
* **协议层**：定义 Session API，让 UI、SDK、MCP 都调用同一套接口。
* **连接器**：SSH、WSL、Docker 等都实现统一的 `Connector` 接口。

---

## 十五、最终定位

> **CoTerm 不是一个 SSH 客户端。**
>
> **CoTerm 不是一个 Terminal Emulator。**
>
> **CoTerm 是一个 AI Native Terminal Collaboration Platform。**

它的核心价值不是“支持 SSH”，而是**把任意终端抽象为一个可共享、可编程、可协作的 Session**。

在这个模型里：

* **人**始终拥有终端控制权。
* **AI**作为协作者接入同一个会话，而不是创建自己的终端。
* **任何 Agent**都可以通过统一的 Session API 或 MCP 接入，而无需关心底层是 SSH、PowerShell、WSL、Docker 还是 Kubernetes。

这也是 CoTerm 与现有 AI Coding 工具最大的区别：它关注的不是“执行命令”，而是**围绕真实终端会话构建人机协作能力**。
